# 우주사진 포토모자이크 로비 스크린 매뉴얼 (V3 Ultimate)

**작성일**: 2026-07-04
**장소**: 포천아트밸리 천문과학관 로비 스크린
**컨셉**: 방문객이 QR로 사진을 업로드하면, 사전에 확보된 수천 장의 우주사진 타일들을 조합해 방문객의 얼굴을 실시간 포토모자이크로 렌더링하여 대형 스크린에 전시합니다.

---

## 1. 주요 기능 및 특징 (V3 Ultimate)

- **완전 자동화 수집 및 최적화 파이프라인**: NASA APOD API를 통해 수십 년 치의 우주 사진 메타데이터를 수집하고, 다운로드, 해상도 최적화, 자동 명도 분류(Dark, Mid, Bright) 및 밸런싱까지 단일 파이프라인으로 처리합니다.
- **초고속 CIE Lab 타일 DB 매칭**: 인간의 시각 인지와 가장 유사한 CIE Lab 색공간을 사용하여, 방문객의 원본 사진 픽셀과 가장 유사한 타일을 초고속으로 매칭합니다.
- **실시간 모자이크 조립 시각화**: 업로드 대기 중 서버에서 100개 타일마다 저해상도 스냅샷을 푸시하여, 사용자 스마트폰에서 모자이크가 실시간으로 조립되는 과정을 미니 캔버스로 시각화합니다.
- **시네마틱 디스플레이 애니메이션**: 대형 스크린에 새 모자이크가 표시될 때 방사형 웨이브, 글로우/스파클, 충격파 등 6가지 효과가 순차적으로 발동하여 몰입감 있는 전시 경험을 제공합니다.
- **iOS/Android 크로스 플랫폼 다운로드**: Blob 기반 다운로드 및 뷰어 Fallback 지원으로 iOS Safari에서도 완벽하게 모자이크 아트 저장이 가능합니다.
- **원터치 무인 운영**: 관리자의 개입 없이, 관람객이 QR을 찍고 스마트폰에서 업로드만 하면 자동으로 그리드가 합성되어 스크린 화면(display.html)에 갱신됩니다.
- **제로 예산, 100% 로컬 아키텍처**: 외부 클라우드 의존성 없이 로컬 노드 서버 기반으로 작동하여 유지비가 없습니다.

- **업로드 대기 중 실시간 타일 조립 시각화**: `upload.html`에서 막연한 스피너 대신 미니 캔버스를 띄우고, 서버와 Socket.io room 단위로 통신하며 100개 배치 단위의 스냅샷을 실시간 수신하여 눈앞에서 모자이크가 완성되어 가는 시각적 즐거움을 제공합니다.
- **대형 스크린 시네마틱 애니메이션(display.html)**: 
  - 방사형 웨이브 딜레이 (중앙에서 외곽으로 타일 비행)

- **관리자 기능 및 로깅 고도화**:
  - `admin.html` 패널 내 Opacity, Blend Mode 등 핵심 옵션 4가지에 대해 보고 및 이해가 쉬운 "상세 설명 접기/펼치기" 토글을 추가했습니다.
  - 터미널 완료 로그에 `총 배치 수`, `고유 타일 수`, `DB 활용률(%)` 지표를 새롭게 출력하여 통계적 가시성을 확보했습니다.
- **브랜드 네이밍 통합**: 전체 페이지의 `<title>`과 UI 헤더를 **"코즈믹 모자이크 | Cosmic Mosaic"**으로 통일해 브랜드 아이덴티티를 확립했습니다.

### 🔒 [보안 & 운영] 개인정보 자동 파기 및 통계 로그 최적화
- **완벽한 개인정보 보호 로직(Startup Cleaner)**: 서버가 기동될 때마다(`app.js`) `public/outputs/` 폴더에 남아있는 과거의 모든 결과물 사진(`.jpg`, `.png`)들을 강제로 자동 삭제하여 관람객 개인정보 유출을 원천 차단합니다.
- **개인정보 동의 웰컴 스크린(Step 0)**: 업로드 페이지 접속 시 곧바로 앨범이 열리는 대신, "사진은 모자이크 작품용으로만 쓰이고 즉시 파기된다"는 안내문과 **[시작하기 (동의)]** 버튼을 거치도록 UX를 개선했습니다.
- **월간 통계용 가벼운 텍스트 로그**: 매번 사진을 생성할 때마다 `logs/stats_YYYY-MM.log` 형식의 가벼운 텍스트 파일에 참여자 통계(시간, 소요시간 등)를 누적합니다. 용량이 극히 작아 영구 보존됩니다.
- **유지보수용 JSON 로그의 3일 자동 파기**: 에러 디버깅이나 타일 좌표 추적 시 필요한 상세 JSON 로그(`logs/history/`)는 서버 기동 시 "3일이 지난 오래된 파일"만 자동으로 선별하여 삭제하므로, 하드디스크 용량 초과를 막으면서도 문제 발생 시 유지보수 골든타임(3일)을 확보했습니다.

## 3. 이전 패치노트 (2026-07-04)

### ⚡ [추가] Extreme Performance Optimization (초고속 렌더링)
- 대형 해상도(1440x1440)에서 16초 이상 걸리던 렌더링 시간을 **2~4초 수준으로 폭발적으로 단축**시켰습니다.
- **연산 압축 및 GC 최적화**: 무거운 `Math.sqrt`를 제거하고, 오차 범위를 미리 정렬하여 조건에 맞는 Top K(60장) 타일을 채우면 남은 수천 장의 타일은 검사조차 하지 않고 조기 종료(Early Exit) 하도록 워커 스레드를 혁신했습니다. 또한 불필요한 배열 생성을 밖으로 빼내어 가비지 컬렉션(GC) 렉을 완전히 제거했습니다.
- **핵심 로직 100% 보존**: 연산 "순서"만 최적화했을 뿐, 사용자 고유의 **"중복 타일 금지(5x5 방어)"와 "점수 공식(거리×0.3 + 페널티×10 + 랜덤)"은 단 1글자도 훼손되지 않았으며 기존과 동일한 품질의 결과물**을 뽑아냅니다.
- **서버 부팅 시 RAM 풀장전 (Pre-load)**: 서버가 켜질 때 5,000장의 타일을 미리 리사이징하여 RAM(메모리 캐시)에 전부 올려둡니다. 첫 요청부터 하드디스크를 읽을 필요 없이 램에서 즉시 픽셀을 복사하여 첫 렌더링 딜레이를 완벽하게 없앴습니다.
  > **[메모리 안정성 체크]** 20x20 픽셀 이미지 1장의 순수 데이터는 약 1.2KB입니다. 5,000장을 전부 RAM에 올려도 고작 **6MB~10MB**의 메모리밖에 차지하지 않습니다. 하루 9시간 내내 서버를 켜두어도 메모리 누수나 시스템 과부하에 전혀 영향을 주지 않는 완벽하게 안전한 용량입니다.

   - 대형 스크린(display.html)에 다운로드용 QR을 추가로 띄우면 관람객의 혼동과 동선 꼬임(사진이 지나가버리는 문제)이 발생할 수 있다는 점에 착안.

3. **True Deduplication (완벽한 중복 제거 로직)**
   - 기존의 평균색(Average Color) 기반 중복 제거가 멀쩡한 타일까지 날려먹던 뼈아픈 실수를 개선했습니다.
   - `scripts/true.dedup.js`를 신규 개발하여 8x8 픽셀 단위로 축소한 뒤 오차 범위 내에서 물리적 이미지가 동일한지 완벽하게 판별하여 진짜 중복된 사진만 삭제하도록 고도화했습니다.
   
4. **폴더 구조 전면 평탄화 (Flattening) 및 네이밍 표준화**
   - 백엔드 소스의 불필요한 하위 폴더(`routes/`, `services/`, `workers/`)를 없애고 `src/` 하나로 압축하여 파일 접근성을 극대화했습니다.
   - 범용 프레임워크 표준에 맞게 폴더명을 직관적으로 변경했습니다. (`server` ➡️ `src`, `frontend` ➡️ `public`, `pipeline` ➡️ `scripts`)
   - 흩어져있던 모든 로그를 `logs/` 폴더 하나로 중앙 집중화하여 모니터링을 편하게 만들었습니다.
   
5. **`old` 아카이브 완벽 분리 및 정리**
   - V2 시절의 낡은 크롤링 스크립트(`fetchAndProcessApod.js`)와 껍데기 뿐인 빈 폴더들, 그리고 사용하지 않는 레거시 코드를 모두 `old/` 내부에 카테고리별로 각을 잡아 영구 격리했습니다.

   - 원본 보존의 원칙을 지키기 위해 `data/` 내부를 `originals`(원본), `optimized`(최적화본), `raw_tiles`(밸런싱된 최종 풀) 구조로 명확히 분리 및 이관.
5. **글로벌 로깅 시스템 적용**
   - 콘솔 출력뿐만 아니라 `data/apod_pipeline.log` 파일에 파이프라인의 모든 작업 내역과 에러 로그를 영구적으로 기록하도록 개선.

## 4. 핵심 시스템 로직 및 작동 원리

### 4-1. 초고속 타일 인덱싱 및 중복 제거 파이프라인
1. **[물리적 중복 제거 (True Dedup)]**: `scripts/true.dedup.js`가 `public/raw_tiles/`에 있는 원본 타일들을 8x8 픽셀 단위로 축소하여 물리적 형태가 완전히 동일한 중복 사진들을 색출 및 삭제합니다.
2. **[리사이징 (Build DB)]**: `scripts/build.db.js`가 원본 타일들을 모자이크 합성용 기본 사이즈(20x20 픽셀)에 맞춰 `public/tiles/` 폴더에 일괄 리사이징합니다.
3. **[CIE Lab 색공간 매핑]**: 리사이징된 각 타일의 평균 색상을 추출해, 인간의 시각과 가장 유사한 CIE Lab 색공간 좌표(L, a, b)로 변환한 뒤 `data/tileDB.json`으로 통합 인덱싱합니다.

### 4-2. 상용 포토모자이크 수준의 중복 방지 및 다채로움 극대화 로직
- **문제 인식**: 단순히 "가장 비슷한 색(Greedy)"만 찾을 경우, 사진에 얼굴이나 하늘같이 넓은 단일 색상 영역이 있으면 5000장의 데이터베이스 중 가장 가까운 1등 타일만 수백 번 반복해서 뽑히는 끔찍한 도배 현상(Clustering Illusion)이 발생합니다.
- **5x5 반경 공간 방어 (Ban Radius)**: 타일을 캔버스에 배치할 때, 배치할 칸을 중심으로 5x5 반경(25칸)을 검사하여 동일한 타일이 단 한 개라도 존재하면 후보에서 즉시 영구 제외시킵니다. 나아가 오차 범위 내의 시각적으로 비슷한 타일들까지 5x5 내부 진입을 차단해 똑같은 패턴이 뭉치거나 줄무늬를 형성하는 것을 수학적으로 완전 방어합니다.
- **Top-K 확률 기반 선택 (Jitter Sampling)**: 무조건 1등 타일만 고르지 않습니다. 전체 DB를 색상 오차 순으로 정렬한 뒤, 상위 60개(Top K)의 우수 후보군을 대량 추려냅니다. 그리고 이 60개 안에서 (색상 거리오차 × 0.3) + (누적 사용 횟수 페널티 × 10) + 미세한 난수(Jitter) 점수를 합산하여 가장 낮은 점수를 받은 타일을 최종 선택합니다. 이렇게 하면 1등부터 60등 타일이 골고루 무작위 섞여 들어가 인간의 눈에는 도배로 보이지 않으면서도 색상은 완벽히 섞여 들어갑니다.
- **최대 사용 횟수 제한 (Max Usage)**: 아무리 좋은 1등 타일이라도, 사진 전체를 통틀어 최대 4회까지만 사용할 수 있도록 하드 리밋(Hard Limit)을 걸어 특정 타일의 비정상적인 범람을 최종적으로 억제합니다.

### 4-3. 다중 사용자 동시 업로드 (병렬 워커 큐)
- **Node.js Worker Threads**: 여러 관람객이 동시에 QR을 찍고 각자의 폰에서 사진을 전송하더라도 서버가 멈추지 않도록 **비동기 큐(Mosaic Queue)**가 작동합니다.
- **병렬 처리**: 서버의 CPU 코어 수에 맞춰 워커 스레드가 백그라운드에서 생성되며, 업로드된 사진들을 순차적으로 동시에 병렬 렌더링합니다. 한 명의 처리가 끝나면 즉시 다음 대기열에 있는 방문객의 사진이 처리되어 대형 스크린으로 부드럽게 송출됩니다.

### 4-4. 스마트폰 다이렉트 다운로드 (UX 최적화)
- 기존에는 대형 스크린에 완성본과 함께 다운로드용 QR 코드를 띄우는 방식을 고려했으나, **여러 관람객이 동시에 참여할 경우 동선이 꼬이고 "내 사진"이 화면에서 빨리 넘어가 버리는 문제**가 있었습니다.
- 이를 해결하기 위해, 사용자가 사진을 전송했던 **본인의 스마트폰 브라우저(`upload.html`) 화면에 완성 직후 다이렉트 다운로드 버튼이 표시**되도록 설계했습니다.
- 따라서 관람객은 대형 스크린에 뜨는 본인의 모자이크 아트를 감상함과 동시에, 자신의 스마트폰 앨범에 100% 안전하고 프라이빗하게 결과물 원본을 소장할 수 있습니다.

## 5. 운영 및 실행 방법

### 서버 시작
동봉된 `start.bat` 파일을 더블클릭하거나 터미널에서 다음 명령어를 실행합니다.
```bash
npm start
# 또는 node src/app.js
```

### 파이프라인 관리 (데이터 업데이트)
타일 DB를 재구축할 때 사용합니다. (이미지는 `public/raw_tiles`에 넣습니다.)
```bash
node scripts/build.db.js
```

### 접속 URL
- 대형 스크린 전시용: `http://localhost:3000/display.html`
- 방문객 스마트폰 업로드용: `http://localhost:3000/upload.html`
- 관리자 패널: `http://localhost:3000/admin.html`
